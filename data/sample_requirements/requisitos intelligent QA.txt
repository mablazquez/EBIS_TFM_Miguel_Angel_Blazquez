Documento de Especificación de Requisitos Técnicos y Funcionales
Proyecto: Intelligent QA (MVP)
1. Información General y Objetivos
●	Título del Proyecto: Intelligent QA — Asistente Inteligente para Aseguramiento de Calidad de Software con IA Generativa.
●	Propósito del MVP: Construir una aplicación web modular en Python (FastAPI + Streamlit) que automatice tareas clave de aseguramiento de calidad (QA): análisis/validación de requisitos, generación de pruebas e ingeniería inversa de código legacy.
●	Distribución: Repositorio público de GitHub preparado para la evaluación del tribunal de TFM.

2. Stack Tecnológico y Configuración de IA
●	Frontend: Streamlit (interfaz limpia, reactiva y orientada a la carga de ficheros con botones dinámicos).
●	Backend: FastAPI (API RESTful para recepción de ficheros, orquestación y endpoints asíncronos).
●	Framework de Agentes / Orquestación: LangGraph & LangChain (grafos de estado para la toma de decisiones, control de flujo y ejecución de tools).
●	Modelo LLM Principal: gemini-3.8-flash vía Google GenAI / Gemini API.
○	Rol del modelo: Su baja latencia y alta capacidad en ingeniería de software y uso de herramientas (tool-calling) permiten usarlo de forma unificada tanto para la clasificación/filtrado inicial de bajo coste como para las tareas agentic complejas de generación de tests y requisitos.
●	Gestión de Entorno: Archivo .env para almacenar variables críticas (GEMINI_API_KEY, nivel de logs, puertos).
●	Gestión y Externalización de Prompts: Todos los prompts de la aplicación (clasificador/guardrail, agentes y tools) deben residir de manera obligatoria y centralizada en archivos de texto dentro de la carpeta data/prompts/. Queda prohibido hardcodear prompts en el código fuente. Se implementará en src/core/config.py un mecanismo centralizado de carga de plantillas que permita resolver, validar y reutilizar los prompts de forma limpia y mantenible.


3. Entradas, Validación Estricta y Manejo de Errores
El sistema debe evitar la ambigüedad en la entrada mediante un filtro previo estricto (guardrail):
●	Tipos de archivo soportados:
1.	Código Fuente: Exclusivamente ficheros con extensiones .java o .py con sintaxis válida de Java o Python.
2.	Documento de Requisitos: Ficheros de texto/markdown/documento que contengan una especificación de requisitos funcional estructurada.
●	Reglas de Validación y Filtro (Guardrail):
○	Un clasificador inicial analiza el archivo subido.
○	Si el documento contiene fragmentos mixtos o código embebido sin ser un archivo de código fuente real, o si no se ajusta a un documento de requisitos válido, el sistema bloquea la ejecución.
○	Mensaje de Error Requerido: En caso de no superar la validación, la interfaz debe mostrar el aviso:"La documentación adjunta no es un requisito ni un fichero de código fuente de Java o Python."

4. Arquitectura de Agentes (LangGraph) y Casos de Uso
La solución implementa dos agentes especializados mediante grafos de LangGraph, cada uno provisto de sus herramientas (tools) específicas:



 

4.1. Flujo A: Agente de Requisitos
Al confirmar un documento de requisitos válido, la interfaz despliega dinámicamente 3 botones:
1.	Verificar inconsistencias del documento:
○	Tool: check_document_inconsistencies
○	Función: Detecta partes incompletas, ambigüedades, omisiones y contradicciones lógicas en el texto.
2.	Verificar requisitos (Normativa):
○	Tool: verify_requirements_standards
○	Función: Evalúa cada requisito bajo criterios de calidad (que sean unívocos, atómicos, completos, verificables y técnicamente viables).
3.	Generar casos de prueba:
○	Tool: generate_test_cases
○	Función: Diseña una matriz de pruebas que abarque casos positivos (happy path), casos negativos y condiciones límite (edge cases).
4.2. Flujo B: Agente de Código Fuente (Legacy)
Al confirmar un archivo de código válido (Java o Python), la interfaz despliega dinámicamente 2 botones:
1.	Generar Requisitos (Ingeniería Inversa):
○	Tool: reverse_engineer_requirements
○	Función: Inspecciona la lógica del código fuente para extraer especificaciones funcionales y reglas de negocio actualizadas.
2.	Generar Tests Unitarios:
○	Tool: generate_unit_tests
○	Función: Genera suites de pruebas unitarias automáticas (JUnit para Java, Pytest para Python) con cobertura sobre las funciones del archivo.

6. Sistema de Trazabilidad y Logs
●	Implementar un logger estructurado en src/core/logger.py.
●	Registrar cada fase del ciclo de vida:
○	Recepción del fichero y metadatos (tamaño, extensión).
○	Veredicto del clasificador inicial (fichero aceptado o rechazado).
○	Llamadas a gemini-3.8-flash y ejecución de tools en LangGraph.
○	Tiempos de respuesta y excepciones capturadas.

7. Estrategia de Evaluación y Validación (TFM)
Para garantizar una evaluación rigurosa del tribunal académico:
●	La carpeta data/ debe contener casos de prueba de referencia (ground truth):
○	Requisitos con ambigüedades conocidas para validar si el agente las detecta con precisión.
○	Ficheros Java/Python de comportamiento conocido para evaluar la cobertura y corrección de los tests generados y de los requisitos inferidos.
